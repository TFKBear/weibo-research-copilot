# 023 · 真实反馈的六项修复（终版）

日期：2026-10-26　状态：已实施　验证：`tools/check.py` 全绿

研究者实际跑了两轮（`20261026T195346-6d31`、`20261026T220106-3452`），
提出六条问题。逐条修，并都补了测试或界面自检。

## 1. 窗口太小，按钮与滚动条被折叠

原来的 `geometry("1120x760")` + `minsize(980,660)`：在 125%/150% 缩放的
笔记本屏幕上，左栏内容比窗口高，滚动条贴边、底部按钮被裁掉，用户会以为
"下面没有了"。

改法：

- 初始窗口按屏幕的 94%×90% 计算并居中；
- Windows 下直接 `state("zoomed")` 最大化；
- 左栏滚轮绑定 `<MouseWheel>`（不绑的话只能拖右侧细条）；
- `minsize` 提到 1100×720。

## 2. 候选帖子数写死 20、每帖 50 条，样本太小

- 新增「候选帖子数」输入框：20–500，默认 **100**；
- 「每帖评论数」默认 **100**，范围 10–**2000**（`MAX_COMMENTS_PER_POST` 从 500 提到 2000）；
- 「本次请求上限」滑块范围提到 20–3000，默认 **400**；
- 新增**实时估算**："候选 100 篇 × 每帖 100 条 ≈ 期望样本 10,000 条；
  约需 N 次请求，上限 M 次"；若请求数不够，直接算出"实际大约只能采到多少条"。

这一步的意义不是"把数字调大"，而是让**样本量与请求预算的冲突在开跑前就暴露**。
以前是设了大样本、被上限悄悄截断，报告里还写着"目标 100 条"。

## 3. 话题标签默认「小米SU7」

改为留空。默认填一个话题会让人误以为已经选好了。

## 4. 助手要懂软件，才能指引操作

`assistant/advisor.py` 新增 `SOFTWARE_GUIDE`：五个区怎么点、每个参数是什么、
一键完成会产出什么、五个常见坑（部分帖子被平台拒绝、热门流不保证窗口覆盖、
轮廓系数低于 0.25、情感需人工抽查、无关立场不进分母）。
并写进 system prompt，要求"涉及操作按第几区→点哪个按钮说，不要只说去设置里调"。

## 5. 图表"过于简单"→ 引入 seaborn 统一视觉

已安装 `seaborn 0.13.2`（+ pandas 3.0.3），在 `charts._setup()` 里应用：

- `whitegrid` 主题、`deep` 配色、标题加粗、网格淡化、去掉上/右边框；
- 输出 dpi 150 → **200**（Word 里缩放也清晰）；
- 字体设置放在 seaborn 之后，避免中文被重置成方框；
- seaborn 缺失时安静回退 matplotlib 默认样式（不把环境差异变成崩溃）。

图表本身从 12 种扩到 **14 种**（新增发布时段热力图、高频词），
全部可在界面勾选或用 `--charts` 指定（见 022）。

## 6. 报告缺第九节 → 结构不稳定

`run_report` 不带 `--scan-changepoints` 时，第九节整节消失，读者的
"一到九"对不上，交付物自检也报错。

改为：**第九节永远存在**。没做事件研究就写清楚"本次没有指定事件日期，
没有做事件对比"，并给出补做方法（界面填日期 / `--event`）。

同时把自检里"图表 ≥9 张"的判据放宽——图表数量是**用户自己的选择**
（界面可以只留核心四张），不该被工具判成缺陷；只有"一张都没有"才是 ERROR。
