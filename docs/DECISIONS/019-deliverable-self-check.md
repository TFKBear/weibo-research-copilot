# 019 · 交付物自检：把"东西齐不齐"变成一条命令

日期：2026-10-26　状态：已实施　测试：`tests/test_deliverables.py`（13 项）

## 为什么需要它

导出目录是研究者**真正拿去写论文**的东西。而这几种失败都不会让程序报错：

- 少了一个 `method_note.md`；
- `analysis_comments.csv` 里混进了 `user_id`；
- 报告与附录把时间窗写成两句不同的话；
- 报告引用了 `cleaning_comparison.png`，但那一次图没生成出来。

程序一切正常，人却在几天后提交论文时才发现。到那时前面的采集、清洗、
分析全白做。所以把它做成可执行的自检，而不是一份"请自行核对"的清单。

## 查什么

`tools/check_deliverables.py`，分四层：

| 层 | 检查内容 |
| --- | --- |
| 完整性 | 11 个必需文件存在且非空（raw / analysis / report / 附录 / 方法说明 / 研究日志） |
| 隐私 | 分析层与原始层都不得出现 `user_id` / `screen_name` / `profile_url` / `location`；原始层必须有 `user_pseudo_id` |
| 结构 | 报告 9 个章节 + 方法卡片 + 已知局限；附录 7 个关键章节；引用的每张 PNG 真的存在；图表 ≥9 张 |
| 口径 | 报告「采集口径」小节与附录「二、采集」的检索口径、时间窗**逐字相同**，实际覆盖一致 |

外加 `--docs`：检查 `docs/DECISIONS` 下决策记录编号是否连续、
`NEEDS-REVIEW.md` / `SPEC-COVERAGE.md` 里 `` `docs/xxx.md` `` 形式的引用是否真的存在。

退出码：0 通过；1 有 ERROR（或 `--strict` 时有 WARN）；2 找不到采集。

## 接到一键自检里

`tools/check.py` 末尾新增「交付物自检」一步。**没有数据的环境算跳过、不算失败**——
刚 clone 下来的人不该因为"还没采过"看到一片红。

## 三个刻意的判断

**一、"缺声明"只算 WARN，不算 ERROR。**
清单里没记录数据使用声明时，数据本身仍然完整、仍然匿好。把它判成致命错误，
会让一次合规导出因为一个元字段被判废。但必须提醒，所以是 WARN。

**二、缺 `stance` 列只算 WARN。**
立场模块是可选跑的。用"没跑立场"去否定整次导出，等于把可选功能变成强制功能。

**三、口径比对只比这两句，不比全部措辞。**
「实际覆盖」附录会多一句"（由已采数据反算）"，那是刻意的说明而不是分叉，
所以用 `startswith` 比对；检索口径与时间窗则要求**逐字**相等。
分得太细会把正常的人话判成错误，自检工具一旦开始误报，人就会开始无视它。

## 覆盖到的真实问题

写这个工具的过程本身就是一次自查：先拿真实产物跑，结果它当场报出
报告与附录的时间窗说法不一致（上一轮已修）。这说明"逐字比对"这条不算过度设计。
