## 1. 一次「假 bug」：僵尸号过滤不该跑，却跑了

你的跑单里出现：

```
- 疑似僵尸号过滤     4 条  （占输入 8.0%）
```

但我在上一轮已经把这一步改成**默认关闭、必须手动勾选**。第一反应是代码有 bug，
查下来不是——**你跑的是旧进程**：

| 事实 | 时间 |
| --- | --- |
| 界面进程启动 | 10-24 **23:43:45** |
| 我把 `filter_bots` 改成默认关闭 | 10-25 **00:51:11** |
| 你的采集运行 | 10-25 **01:02:57** |

Python 把模块读进内存后**不会热更新**，那个进程里跑的还是修改前的代码
（当时中度档确实包含僵尸号过滤）。

### 修复：让这种事以后一眼可辨

- 窗口标题带版本号：`博研助手 v0.2.0`
- 日志每行带时间戳
- 启动横幅打出「版本 / 清洗管线版本 / 启动时刻」
- 启动时明确提示：**「若刚更新过代码，请关闭窗口重新启动——程序不会热更新」**

这不是给你看的客套话。没有这三行信息时，我判断这件事花了一次完整的代码审查，
而且结论还只能靠猜；有了它们，下次对一眼时间戳就完事。

### 顺带说明：那 4 条被删的是什么

```
[drop_suspected_bots:粉丝0] 支持小米[good][good][good]
[drop_suspected_bots:粉丝2] 有底盘吗？不会是还坐在电池上吧
[drop_suspected_bots:粉丝2] 今年烧了多少辆车了？质量真好
[drop_suspected_bots:粉丝0] 问界不好？你啥意思，没收钱是吧
```

**四条全都是真实用户的真实表达**，只是因为账号粉丝少（0–2）就被当成僵尸号。
而且你能看到清洗后的粉丝数均值从 88.5 万涨到 96.2 万——这就是清洗报告的
作用：它把「删掉低粉用户会抬高样本的账号层级」这个偏差直接摆在你面前。

这份数据本身就是「粉丝数不等于僵尸号」最好的证据。
所以这个开关**保持默认关闭**是对的，不要改。

## 3. 标定：我原来的阈值 0.82 是错的

模型第一次真的跑起来，就发现默认阈值形同虚设。

**问题**：bge 系列在中文短句上的余弦相似度是「压缩」的 ——
两句都在推销、措辞完全不同的话，相似度也只有 0.6 上下。
我用 0.82 当门槛，结果是**一条都抓不到**。

**这比功能不可用更危险**：
界面会显示「AI 营销识别：0 条」，清洗报告一切正常，
你会以为"这批数据没有营销内容"——而实际上只是门槛高到失效。
一个**静默失效**的功能，比一个报错的功能危险得多。

**标定做法**（`tools/calibrate_ai.py`）：
- 正样本 12 条自然口吻的营销文案（刻意与内置模板措辞不同，避免自己考自己）
- 负样本 80 条你的真实评论
- 分别计算「与最近模板的相似度」

**结果**：

| | 与最近模板的相似度 |
| --- | --- |
| 营销文案（12 条） | 0.644 – 0.844，中位 0.734 |
| 真实评论（80 条） | 0 – 0.606，中位 0.515 |

两者**完全可分**，中间有 0.038 的空隙。取 **0.62** 作为默认阈值。

### 这条经验要记住

阈值不是拍出来的，是量出来的。**换模型、换语料、换领域，都必须重新标定**
（`python tools/calibrate_ai.py`）。这一条已经写进代码注释和配置说明里。

## 4. 在你真实数据上的结果

```
会话：20261025T010257-38c3    评论：50 条
营销话术命中 0 条；协同行为命中 0 条，共 0 个簇
```

**这是正确结果，不是失效**：
- 标定表明阈值能抓到营销文案（12/12），所以不是门槛失效；
- 这 50 条是热门评论流里高互动的真实讨论，本来就不该有水军。

但也要说清楚局限：**样本只有 50 条**，协同行为需要至少 3 条互相高度相似，
50 条的样本量本来就很难形成簇。想看协同行为，得上几百条以上。
