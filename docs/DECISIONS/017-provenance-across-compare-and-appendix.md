# 017 · 让"口径"贯穿到对比与附录

日期：2026-10-26　状态：已实施　测试：`tests/test_compare.py`、`tests/test_reproducibility.py`

上一轮把「采集口径」写进了报告正文。这一轮补的是另外两个出口：
**跨话题对比**和**可复现性附录**。理由很简单——口径只写在报告里，
别人拿附录复现时仍然会拿两份不同的东西当同一个口径比。

## 1. 跨话题对比：时间窗与检索口径现在是"不可比"的理由

原来的可比性检查已有 7 条（采集模式 / 后端 / 排序 / 选帖数 / 每帖上限 /
清洗档位 / 二级评论）。新增两条：

| 参数 | 为什么它更致命 |
| --- | --- |
| 检索口径（话题 / 关键词全文） | 话题聚合是主动参与者，关键词全文混着路过提及的人 |
| 评论时间窗 | 窗口不同 = 覆盖时段不同，占比与绝对量都不能直接比 |

时间窗在参数里是 **dict**，而可比性判断靠"同一 key 的取值集合是否只有一个"，
dict 不可哈希，直接塞进去会抛 `TypeError: unhashable type: 'dict'`。
所以统一压成一句 `comment_window_label`（如 `2026-09-01 00:00 ～ 2026-09-30 23:59`），
既可比，也正好是报告里能直接读的说法。老数据没有这个字段时给"不限时间"，
不是给"未记录"——因为它确实是"没设窗口"，不是"不知道"。

## 2. 附录：补三项最容易漏的复现信息

`collect_facts()` 现在会把三项写进 `## 二、采集`：

- **检索口径**（话题聚合 / 关键词全文，且说明后者含仅提及的帖子）；
- **评论时间窗**；
- **实际覆盖**，并注明"由已采数据反算，不是计划值"。

这三项同时从参数表里**移除**：它们是派生值，留在表里会被读成"采集时填的参数"。

顺带修了两处：

- `_value()` 遇到 dict 会打出 Python repr（`{'active': True, ...}`），
  附录是给人读的，现在渲染成 `active=是；label=…`；
- 「采集约束」那段原来写死"评论取自热门评论流"，现在按实际排序分流：
  按时间取的时候，真正的偏差是"窗口早期评论可能采不足"，而不是"高互动偏置"。

## 3. 一处刻意的克制

没有给"帖子级时间窗"（按发帖时间筛选候选帖）。
它听着合理，但会把两件事混在一起：**帖子发布时段**与**评论发生时点**。
研究"某段时间的讨论"要的是后者，而一条 9 月发的帖子在 10 月仍然会积累评论。
真要做帖子级筛选，得先想清楚研究问题，不能顺手加一个筛选项让它看起来更强。
