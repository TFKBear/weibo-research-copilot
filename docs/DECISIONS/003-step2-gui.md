## 2. 一处技术选型调整：用 ONNX 而不是 BERT + torch

你说"引入 bert"。实现时我把运行方式换成了 **ONNX Runtime 跑 bge-small-zh-v1.5**，
理由有三个，都影响你能不能真的用起来：

1. **体积**：torch CPU 版约 200MB+，onnxruntime 约 20MB。做成桌面程序时这个差别是决定性的。
2. **依赖**：你机器上 `onnxruntime` 和 `tokenizers` **已经装好了**（我检查过），
   而 torch 没装。少装一个 200MB 的包，少一类装坏的可能。
3. **启动速度**：加载 23MB 的 ONNX 模型是秒级，torch 要好几秒。

效果上没有妥协：bge-small-zh-v1.5 就是 BERT 架构的中文句向量模型，
只是换了个推理引擎。所以"有没有 AI 元素"这件事没有打折——
它仍然是神经网络 + 语义相似度，只是不再拖着 torch 走。

**如果你坚持要用 torch / HuggingFace 原生加载**，告诉我就行，换一层实现大概半小时，
但我建议不要——收益是零，成本是几百 MB。

## 3. 我主动收紧了一处（需要你知情）

需求文档里中度档写的是「去除粉丝数 <5 **且** 注册 <30 天的疑似僵尸号」。
实机抓取后确认：**评论接口不返回注册时间**，这个"且"字拿不到。

只按"粉丝数 <5"删人的后果是：真实的低互动用户（新用户、退休用户、
只看不发的沉默用户）会被整批删掉。而我们正在研究的恰恰是"公众意见"，
把这些人的声音删掉，结论就只代表活跃用户了——这正是产品宪法第 2 条要防的事。

所以我的处理是：

- 该步骤**不随档位自动启用**；
- 界面上单独一个勾选框，默认**不勾**，文案直接写明"可能误伤真实的低互动用户"；
- 清洗方法说明里如实记录"是否启用、仅依据粉丝数、未校验注册时间"。

如果你认为它应该默认打开，改一个默认值即可，但我建议保持关闭。

## 4. 图形界面

### 形态
单窗口，左侧配置（四个分组）+ 右侧日志。不追求"仪表盘感"，
因为真正的分析产物是导出的 CSV 与方法说明，界面只负责把参数收对、把过程讲清楚。

### 启动方式

| 方式 | 命令 | 会不会弹黑窗 |
| --- | --- | --- |
| 双击 | `启动博研助手.vbs` | **不会**（用 pythonw 静默启动） |
| 命令行 | `python -m wrc.gui` | 会 |
| 双击 | `main.py` | 会 |

`.vbs` 那个是为你这次提的"尽量别弹终端"做的：它用 `pythonw`（无控制台的 Python）
并以隐藏窗口方式启动，屏幕上不会闪任何东西。

### 关键取舍
- **耗时操作全在后台线程**，主线程只画界面。否则点一下"检索"窗口就假死。
- **停止是协作式的**：点停止后，当前这篇帖子采完才停，已采数据全部保留。
  不做"立刻 kill"——那会留下半截数据，对研究反而更糟。
- **AI 未就绪时直接拦下**，不静默降级。理由：用户勾了 AI 却没跑，
  如果照常输出"清洗完成"，那份数据的清洗档位就是假的。

## 5. 关于 exe

你说先不管，我就没做 PyInstaller 打包。
现在的替代方案是 `启动博研助手.vbs`——双击即开、无黑窗，体验上等价于一个 exe，

- 主要风险在 Playwright 的驱动打包，需要额外调；
- 到那一步我再单独做一轮，不混在功能开发里。
