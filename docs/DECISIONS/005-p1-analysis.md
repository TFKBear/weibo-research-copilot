## 2. 真实数据上验证出的四个问题

### ① 本地情感模型在中文微博上不可靠（必须披露）

用 `Xenova/distilbert-base-multilingual-cased-sentiments-student`（129MB，int8）
在 25 条真实评论上实测：

- 18/25 条置信度 < 0.6
- `@人民日报 @央视新闻` 被判为 **positive**
- 它抓的是"希望/支持/建议"这类字面词，读不出反讽

**处理**：它只作"粗筛参照"，方法卡片里自动写入这条局限；
报告里给出本地通道的低置信占比，让研究者自己判断该不该信。
**没有**把它包装成"AI 情感分析准确率 XX%"——那是自欺。

### ② 抽样下限：偏离了需求文档，但必须偏离

需求写的是 `min(200, 总数×5%)`。实测 25 条评论时，5% = 1.25 → 只抽 2 条，
算出的不一致率是 50%（噪声），却会被当成"信度不达标"的正式告警。

**处理**：加 `SAMPLE_FLOOR = 30` 下限，小样本全量比对，
偏离原因写进代码注释与方法卡片。**任何抽到 2 条的比率都不该进论文。**

### ③ 模型目录撞车导致"假的高分"（最危险）

`models/` 下同时有句向量模型和情感分类模型，两者的 ONNX 文件**都叫
`model_quantized.onnx`**。`detect_status` 按"最大的 .onnx"选中了情感模型，
于是分类器的 **3 维 logits 被当成句向量**，聚类照样跑完，
轮廓系数算出 **0.8192**——一个漂亮但完全虚假的数字。

如果没有人去核对 `embedding_dim`，这个结果会一路走进论文。

**处理**（三层）：
1. 配置拆成 `ai_embedding_model_dir` 与 `ai_sentiment_model_dir`，各指各的目录；
2. `OnnxEmbedder.encode()` 出口加维度自检（<32 维直接报错并说明原因）；
3. 分类器遇到 3 维输出（只有编码器、没有分类头）时明确拒绝，而不是猜。

修复后重跑：`embedding_dim: 512`，轮廓系数 **0.1233**——这才是这批数据的真实水平。

### ④ KMeans 在重尾数据上切出"伪社群"

用户社群聚类第一版结果：**43 人一簇 + 两个 1 人簇**。
原因是"获赞数""粉丝数"是重尾分布，一个明星账号能把标准差拉爆。

**处理**：计数类特征先取 `log1p` 再标准化；并对"少于 3 人的簇"显式告警，
说明这是"把极端账号切出来"而不是找到了社群，只能当个案看。

修后仍是 44 + 1，并如实报警——因为**在 46 条评论、45 个用户里，
本来就不存在可识别的社群结构**。工具现在的说法是正确的。

## 3. 两个刻意的设计选择

### K 不预判
先扫描 2..k_max 的轮廓系数给出建议值，再由研究者确认。
强制用户先定 K，等于把自己的先验塞进别人的研究设计。

### 关键词算的是"这一簇区别于别簇的用语"
不是"这一簇最常用的词"。后者在每个簇里都是"小米""汽车"，没有信息量。
所以用类内词频 / 全局词频的比值（c-TF-IDF 思路）。
