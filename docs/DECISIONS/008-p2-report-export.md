## 1. 为什么是 Word，不是 PDF

### 做了什么

`wrc/analyze/docx_export.py`：把报告 Markdown 转成 `.docx`，
标题用 Word 的 Heading 样式、表格是真表格、图片嵌入、方法卡片的等宽块保留。

界面「开始分析」和 `python tools/run_report.py` 都会顺手生成一份 `report.docx`。

### 为什么这么选

- **不引 Markdown 解析库**。本工具只产出固定形态（标题/表格/图/代码块/列表/引用），
  为这几种结构装一个通用引擎不划算；通用引擎对"代码块里其实是方法卡片"
  这种语境的排版还不如手写。全部解析逻辑约 130 行。
- **不生成 PDF**。PDF 要排版引擎（reportlab / weasyprint），装得上，但会显著
  拉高安装体积与失败面——而 Word「另存为 PDF」本来就是研究者要做的下一步。
  这条写进了 `docs/NEEDS-REVIEW.md` 6c，留给你决定要不要加。
- **图片按目录相对解析**。找不到图不报错，只在该处留一行
  `[图片未找到：xxx.png]`。报告宁可少一张图也要能打开。

### 一个容易忽略的中文细节

python-docx 默认模板的字体是西文为主，中文会回退成宋体、字号不协调。
所以显式设了 `w:eastAsia`（正文宋体 / 标题黑体）+ 页边距 2.6cm，
打开就是"像一篇论文"的样子，而不是"像导出的数据"。

### 有一个坑，值得记

`cell.text = ""` 会往单元格塞一个空 run，之后 `add_run` 的格式就落到 `runs[1]`，
表头加粗悄悄失效。测试断言 `runs[0].bold is True` 才把它抓出来。
**测试写"表头是粗体"这种细节不是洁癖**——它是 Word 里最显眼的可读性差别。

## 2. 交叉表进报告（第五节）

需求里"聚类 × 属性交叉表 + k-匿名抑制"的抑制逻辑 P1 就写好了，
但一直没接进报告——等于有护栏却不在路上。

现在 `build_analysis_report(crosstab=...)` 会输出第五节，并在真实数据上
**真的触发抑制**：

```
交叉表（最小可展示样本 n≥5）
簇0                  11         7         7
簇1                   9         —         —
簇2                   —         —         —
簇3          （样本量过小，不予展示）

注：4 个单元格因样本量 <5 显示为「—」。
注：1 个分组整体样本量 <5，整行不予展示。
```

（真实会话 `20261025T010257-38c3`，46 条 / 4 簇）

### 三点自我审视

1. **簇2 整行都是 `—`**：它自己有 5 条，但分摊到三个情感类别后每格都 <5。
   这是 k-匿名在真实数据上的正常后果，不是 bug。报告里已有注说明。
2. **抑制后表的可读性变差**。这是伦理换来的，不该偷偷放宽阈值。
   如果论文需要更强的表，办法是**扩大样本**，不是调 `min_n`。
3. **仍然没有真正的"人口属性"**。微博评论接口不返回性别/年龄/学历，
   本工具也不推断。现在的分组属性是情感倾向与话语簇——它们不是敏感属性，
   被抑制只因为样本量没有解释力。这条在 `crosstab.py` 的模块注释里写明了。

## 附：交叉表也进了导出层（补记）

后面补上的一步：交叉表不只在报告里出现，还作为
`analysis/crosstab_discourse_sentiment.csv` 一起导出，**抑制在数据层完成**。

原因是需求（模块 C）的原话是"当某聚类样本量 <5 时自动抑制该交叉表"。
如果抑制只发生在界面或报告排版里，研究者把 `analysis_comments.csv` 拉到 Excel
自己交叉一下，k-匿名就完全绕过去了。护栏必须立在数据出口上。

导出文件的三条约定：

| 情况 | 单元格写法 | 为什么 |
| --- | --- | --- |
| 计数 ≥ min_n | 数字 | — |
| 计数 < min_n | `—` | 抑制；不用 0（0 的含义是"该类别没有评论"），也不用空（Excel 会当缺失值跳过） |
| 该类别在本组完全没出现 | `0` | 这是真值，不能和"被抑制"混成同一个符号 |
| 整组 < min_n | 整行 `—`，`备注`写"整组样本量 <5，不予展示" | 读者该知道这里被压制过，而不是以为没有这个簇 |

还有一处容易错：整组被抑制时"该组总样本"必须仍然照实给。
因为抑制后单元格全是 `None`，直接 `sum()` 会算成 0 ——
"该组 5 条评论"会被写成"该组 0 条"，那是凭空造出来的数字。
所以 `CrosstabResult` 单独保存了一份抑制前的 `group_totals`。
