# 021 · 合并：一次点击走完 采集 → 清洗 → 分析 → 报告

日期：2026-10-26　状态：已实施　验证：`smoke_gui` 断言 + `tools/check.py` 全绿

## 为什么合并

真实运行（`20261026T195346-6d31`）暴露的问题不是 bug，是**流程设计**：
研究者点了「开始采集并分析」，拿到的是有数据、有清洗、有导出的半成品，
但 `report/` 根本不存在——因为分析还是另一个按钮。

工具不能要求使用者记住"还有第二步"。按钮上写着"采集并分析"，
那就应该真的分析完。

## 改成什么样

**界面**：主按钮改为「一键完成：采集 → 清洗 → 分析 → 报告」。
采集与导出结束后，自动接手分析（情感 / 立场 / 聚类 / 时间演变）并生成
图表、`report.md`、`report.docx`，然后提示打开目录。

分析区新增一个开关（默认开）：
「采集完成后自动跑上面勾选的分析并生成报告（一次完成）」。
关掉它就回到"只采数据"，之后仍可用「开始分析并生成图表与报告」单独跑。

**命令行**：`wrc run` 默认一路跑到底，转发给 `tools/run_analysis.py`
与 `tools/run_report.py`（不把 matplotlib/sklearn 拉进采集链路）。
只想拿数据的人用 `--no-analysis`，它会打印后续命令。

## 三个边界处理

1. **分析失败不毁数据。** 采集、清洗、导出已经落盘，分析出错只是没有报告；
   日志会明说"数据与导出不受影响，可稍后单独重跑分析"。
2. **不勾任何分析项时不做无意义的空跑。** 自动分析开关开着但三项全关，
   就当作"只要数据"，直接进入打开目录的询问。
3. **分析仍可单独重跑。** 原有按钮保留——改方案、换事件日期、只补跑立场，
   都不必重采一遍。

## 为什么不做成"一个巨大的函数"

分析链路要读清洗后数据、建模型、画图、出 Word，且每一步都可能因
LLM 不可用或模型缺失而降级。合并的是**入口**，不是实现：
界面仍走 `_on_analyze` 这条路，命令行转发给既有脚本。
这样"合并"不会把两条已经验证过的路径变成第三条未验证的路径。

## 一处诚实的代价

一次点击现在可能要跑几分钟（几百条评论的情感 + 立场 = 几十次模型调用）。
所以按钮文案不再写"开始采集并分析"这种模糊说法，而是把步骤列出来；
开关旁边也写清"一次完成"。让等待是可预期的，而不是让人盯着转圈猜。
