## 1. 话语簇 × 立场

### 为什么需要它

前面两张表各回答一半：
- 「簇 × 情感」说明**哪些簇情绪更负面**；
- 「情感 × 立场」说明**情绪与态度如何错位**。

但"不同话语阵营的态度结构是否不同"——比如某一簇全是政策执行细节的讨论、
另一簇全在骂双轨制——只有「簇 × 立场」能看出来。

### 真实数据（#延迟退休#，492 条，K=2）

| 话语簇 | 支持 | 反对 | 中立 | 无关 | 合计 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 簇0 | 14 (7%) | 97 (46%) | 46 (22%) | 52 (25%) | 209 |
| 簇1 | 46 (16%) | 177 (63%) | 38 (13%) | 22 (8%) | 283 |

**读法**：簇1 的反对率（63%）明显高于簇0（46%），
而簇0 的「无关」占比（25%）是簇1 的三倍——说明簇0 混入了大量
不针对议题本身的表达（签到、闲聊、纯表情）。
这解释了为什么簇0 看起来"情绪没那么负面"：它的基线本来就被稀释了。

### 实现

- `stance_crosstab.stance_by_discourse()` 复用同一个 `build_crosstab`，
  抑制规则与别处完全一致；
- 渲染器做了**参数化**（`title` / `group_label`），
  「立场 × 情感」与「簇 × 立场」共用一份代码——各写一遍必然各错一遍；
- 导出 `analysis/crosstab_cluster_stance.csv`；
- 报告第六节拆成三个子表（一、话语簇 × 情感；二、情感 × 立场；三、话语簇 × 立场）。

## 2. 事件节点对齐（event study）

### 三条不可妥协的规则

**一、事件日期只能由研究者给。**
工具可以从数据里找出"评论量最大的那天"，但那是**数据特征**，不是**事件**。
把峰值日当事件日再宣称"事件效应"，是典型的事后归因。
所以 `--event` 必须显式传；没传就不出这一节。

**二、窗口两侧样本不足时，只报数不给结论。**
每侧至少 30 条才算占比差（`MIN_WINDOW_N`），少于这个数只写"样本不足"。

**三、统计检验要标明假设，且不替研究者定口径。**
给的是**两比例 z 检验**（正态近似），只在"四个期望频数都 ≥5"时给出；
不满足就明说"正态近似不可靠"。p 值只是参考——用不用它、
显著性水平取多少，是研究设计与期刊口径问题。

### 窗口边界（必须写进论文）

- 前段：`[事件日 − pre, 事件日)` —— **不含事件当天**
- 后段：`[事件日, 事件日 + post]` —— **含事件当天**

这个不对称是刻意的：事件当天的评论已经在"事后"语境里产生。

### 演示运行（**不是研究结论**）

因为研究者还没给真实事件日，我用**数据峰值日**（2026-09-29）跑了一遍，
只为验证功能，报告里明确标了"演示事件（峰值日）"：

| 指标 | 前段 n | 后段 n | 变化 |
| --- | ---: | ---: | --- |
| 立场·反对 | 82 | 103 | **+22%**（p=0.002） |
| 立场·中立 | 82 | 103 | −14%（p=0.013） |
| 情感·负面 | 82 | 103 | **+33%**（p<0.001） |
| 情感·中性 | 82 | 103 | −28%（p<0.001） |

这张表本身是可信的（数据、窗口、检验都对），**但事件选择是错的**：
峰值日是结果，不是原因。真实使用时必须换成外部事件（政策公布、官媒发声等）。

> **后续处置**：研究者随后确认 2026 年的讨论是 2024-09-13 文件的**实施效应**，
> 公布日与数据相差两年（见 §4、§6）。因此默认报告已撤下这一节，
> 只保留第九节的"话语转折点扫描"，并明确标注它不是事件研究。

### 工程实现

| 层 | 改动 |
| --- | --- |
| 分析 | 新模块 `wrc/analyze/events.py`（窗口切分、z 检验、渲染） |
| 存储 | 事件写回 `collection_runs.params_json` 的 `events` 字段，重建报告不必重敲 |
| 图表 | `timeseries_evolution.png` / `stance_trend.png` 上画事件竖线 |
| 报告 | 第九节「事件前后对比」+ 事件线图 |
| 入口 | `--event 日期[:标签[:前N:后N]]`（可重复）；界面「4 · 分析」新增事件日期输入框 |

事件线画在"第一个不早于事件日的桶"上——宁可画晚一格，也不画早：
把事件标早了会让人误以为变化发生在事件之前。

## 4. 研究者上传决定原文后的核对结果（关键）

研究者提供了中国政府网的原文 PDF（已存 `docs/sources/延迟退休决定_中国政府网.pdf`）。
从 PDF 里抽出的时间是：

| 事项 | 日期 |
| --- | --- |
| 全国人大常委会通过并公布 | **2024-09-13**（新华社当日 17:17 发稿） |
| 决定施行 | **2025-01-01** |
| 最低缴费年限调整起点 | 2030-01-01 |

**这暴露了一个必须先解决的问题：事件与数据相差两年。**

- 事件：2024-09-13
- 现有数据：2026-09-06 ～ 2026-10-25（492 条）

用工具跑一遍就能看到它拒绝给出结论（这是正确行为）：

```
公布日 2024-09-13：前 0 条 / 后 0 条 → 一侧完全没有数据
施行日 2025-01-01：前 0 条 / 后 0 条 → 一侧完全没有数据
```

**所以事件研究这一节现在不能用现有数据产出**。这不是工具的问题，
是数据的时间范围覆盖不到事件。三条出路（要研究者选）：

1. **补采 2024 年 9 月前后的评论** → 做真正的"公布日效应"；
2. **改研究问题**：不做事件研究，用现有数据分析"政策实施一年半后的态度结构"
   （现有八节都成立，只是没有第九节）；
3. **换成 2026 年某个可核实的官方动作做事件** → 需要研究者给出文件名，
   由我核实发布日后再跑。

### 为避免"用结果定义原因"，新增了转折点扫描（只作线索）

`--scan-changepoints`：逐日当分界、比较前后窗口的占比差异，按变动幅度排序。
**它的名字里就写着"不是事件研究"**，报告里也用一句话钉死：

> 把它当「去看哪段时间」的线索，再去查那几天有没有可核实的公共事件。
> **不要**直接把排名第一的日期写成「事件日」——那是用结果定义原因。

真实数据结果（立场，前 7 / 后 7）：

| 候选日 | 前段 n | 后段 n | 反对 |
| --- | ---: | ---: | --- |
| 2026-09-08 | 30 | 108 | 17% → 42%（+25） |
| 2026-09-28 | 65 | 119 | 51% → 76%（+25） |
| 2026-09-29 | 82 | 103 | 55% → 77%（+22） |
| 2026-09-27 | 52 | 132 | 52% → 73%（+22） |
| 2026-09-21 | 88 | 83 | 33% → 54%（+21） |

排名靠前的是 9 月上旬与 9 月底两段，**不对应任何可核实的官方发布**——
更可能是讨论自身的热度周期。这恰好说明：不能拿它当事件日。

### 顺带修掉的一个 bug

`--no-events` 原本清不掉已保存的事件：`resolve_events` 把 `None` 与 `[]`
都当假值，于是"明确不要事件"被当成"没指定，读回旧的"。
现在两者严格区分（`None`=读回，`[]`=清空），并加了回归测试。

## 5. 关于检索方式

内置 `web_search` 在本环境持续返回 401（搜索端点鉴权失败，属用户侧配置），
`web_fetch` 被沙箱限制。研究者指示：**不再用内置搜索，改用 agent search**。

实际做法：用本机网络能力直接请求 DuckDuckGo / 百度 / Bing 的 HTML 结果页，
抓取标题、摘要与链接；官方结论以政府网原文为准。
本次即由该方法定位到 2024-09-13 的官方原文，并下载核对了 PDF。

## 6. 研究者的解释改变了分析框架（关键转折）

研究者指出：2026 年的热议**不是**因为出了新政策，而是 2024 年文件的实施效应——
2026 是政策落地后的第一个完整年份，个人化计算、弹性退休细则、网络传言与焦虑叠加。

这一解释直接改变了分析设计：

| 原设计 | 现设计 |
| --- | --- |
| 事件研究：以"公布日"为界比前后 | **不做**——公布日与数据相差两年，窗口内没有数据 |
| 假设：讨论是"事件冲击" | 假设：讨论是"实施期的关注点迁移" |

### 因此新增：术语随时间的变化（`wrc/analyze/terms.py`）

`--term-trends`（默认开启）按 7 天分段，统计每个词在**该段评论中的出现率**，
再比较首末段的升降。它回答的是「**关注点在变什么**」，不是「态度在变什么」。

真实数据结果（492 条，7 天一段）：

| 上升 | 首段 → 末段 | 下降 | 首段 → 末段 |
| --- | --- | --- | --- |
| 社保 | 8% → 30%（+22） | 老年人 | 20% → 2%（−18） |
| 工资 | 2% → 15%（+13） | 提前退休 | 18% → 2%（−16） |
| 年轻人 | 4% → 15%（+11） | 返聘 | 4% → 0% |

**这支持了研究者的核心判断**：讨论从"政策文本层面"（老年人、提前退休）
迁移到"个人与代际层面"（社保缴纳、工资、年轻人）。

**但不支持其中三个具体说法**——这些词在数据里几乎不出现：

| 研究者提到的驱动因素 | 数据中的出现率 |
| --- | --- |
| "退休年龄计算器" → `计算` | 全程 0% |
| "弹性退休细则" → `弹性` | 全程 0% |
| "90 后 65 岁传言" → `90后` | 最高 1% |

也就是说：**方向对，机制描述与语料不符**。论文里若照搬"计算器与弹性退休细则",
会缺少语料支持；更稳的写法是"讨论重心从政策文本转向个人缴费与代际负担"。

### 一个重要的对照结果

- 立场：反对比例稳定在 55%～77%，没有单向趋势；
- 术语：迁移明显（社保 +22 个百分点）。

**两者放在一起才成立**：态度没翻转，关注点在具体化。
这就是"实施期效应"而非"事件效应"的实证形态。

### 工程实现

- 只拿样本量 ≥20 的段参与首末比较——末尾常是半个采集日（1–2 条），
  拿它当"末段"会让任何词都显示暴跌。
- 出现率按"提到该词的评论占比"计，不用词频（防刷屏重复带偏）。
- 结果里明确写"未做显著性检验""同义词未合并"。

全量 **360 项通过**（新增 `tests/test_terms.py` 9 项）。

| 回归测试 | `test_report_states_implementation_phase_framing` 防止这段声明被后续改动悄悄删掉 |

### 7.2 p 值：**A 保留现状**

保留「变化百分比 + p 值 + 假设检查」，并在报告里注明 p 值只是参考。
研究者需能解释：两比例 z 检验、正态近似、四个期望频数均 ≥5 的前提。

完整选项对照（A 保留 / B 去掉 / C 卡方 + Cohen's h）保留如下，供后续改口径时查：

| 选项 | 报告里出现什么 | 适合 |
| --- | --- | --- |
| A 保留（现状） | 变化百分比 + p 值 + 假设检查 | 你能自己解释 z 检验 |
| B 去掉 p 值 | 只给变化百分比与样本量 | 避免被问"为什么不用更严格的检验" |
| C 换成更严格的 | 卡方检验 / 带连续校正的检验，并给效应量（Cohen's h） | 期刊要求统计量 |

**我倾向 A 或 C**：只给百分比而不给任何不确定度，反而更容易被质疑。
