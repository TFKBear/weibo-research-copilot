# 018 · 口径一致性、空状态与方法说明的时效性

日期：2026-10-26　状态：已实施　测试：`tests/test_provenance_consistency.py`、`tests/test_export.py`

本轮三件事，主题都是「别让同一件事在四个地方说四遍还不一致」。

## 1. 口径一致性回归测试（新文件 `test_provenance_consistency.py`）

同一批数据现在会出现在四处：报告正文的「采集口径」小节、可复现性附录的「二、采集」、
方法卡片的「一、数据」、导出的 `method_note.md`。

四条路各写一遍推导，迟早分叉；而分叉的后果不是"显示不一致"这么轻——
论文里两处写的时间窗不同，审稿人只会得出一个结论：这份数据来源不可信。

所以新增三个测试，用同一份采集参数与数据盯住：

- 时间窗 label 在报告、附录、卡片三处**是同一个字符串**；
- 检索口径三处都点明「关键词全文」，不会有一处悄悄写成话题聚合；
- 实际覆盖的起止时间三处一致，且**不是**照抄计划窗口
  （数据只落在 9-20，就不能声称覆盖到 9-30）。

另外验证「排序未生效」这件事：研究日志缺失时三处都不许表态，
只有日志明确说 `sort_applied=false` 时才一起写"未生效"。

## 2. 方法说明的局限段跟着口径走

`method_note.md` 的「五、已知局限」原来写死一句话：
*评论来源为平台热门评论流，偏向高互动评论*。

这句话在按时间采集时**是错的**——那时真正的偏差不是高互动偏置，
而是"窗口早期的评论可能采不足"。现在按实际口径分流：

| 采集排序 | 局限怎么写 |
| --- | --- |
| 热度（默认） | 热门流偏高高互动；**且时间不单调，设了窗口也不保证采全** |
| 时间 | 窗口早期评论可能采不足，实际覆盖见附录，**不要直接照抄设定的窗口** |

并固定增加一条：检索口径若是「关键词全文」，样本含仅提及该词的帖子，
不等于话题参与者。

## 3. 界面的空状态

第一次打开时帖子列表是空的。原来什么都不说，用户会以为程序坏了或自己漏了哪步。
现在列表下方常驻一句引导：

> 还没有候选帖子：① 在上方填话题 → ② 点「检索帖子（第一步）」 → ③ 在这里勾选要采评论的帖子

检索完如果没有结果，提示会换成"换个说法再检索 / 用推荐话题 / 先检查登录态"，
而不是留一个空列表让人猜。`smoke_gui` 里加了断言盯住"空列表时提示可见、
有数据后自动隐藏"。

## 一处没有做的事

没有做"新用户向导页"（分步弹窗那种）。理由：这个工具的使用者是要写论文的人，
一个可关闭的引导面板比弹窗更不打扰；而当前的空状态提示已经把"下一步是什么"说完。
如果真人可用性测试证明还卡在别处，再加也不迟——那正是第 4 步验收要回答的问题。

## 4. 写测试时发现真不一致（已修）

写完一致性测试后拿**真实产物**对了一遍，报告与附录确实分叉：

| 项目 | 报告原话 | 附录原话 |
| --- | --- | --- |
| 检索口径 | 话题聚合（q=#话题#），样本是主动参与该话题的帖子 | 话题聚合（q=#话题#） |
| 评论时间窗 | 未设置（采该帖可见的最新评论） | 不限时间 |

不是笔误：两处各自拼字符串，一边带了解释、一边没带。于是把「唯一说法」沉到
`analyze/collection.py` 的 `search_mode_text()` / `window_text()`，
报告、附录、方法卡片三处都调它；`method_note` 的局限段也改成按口径分流。
新增断言 `test_wording_comes_from_one_place`：四处必须**逐字**包含同一句，
而不是"意思差不多"。

修完后真实产物三处逐字一致（已用脚本核对）：
`检索口径：话题聚合（q=#话题#），样本是主动参与该话题的帖子`
`评论时间窗：不限时间（采该帖可见的最新评论）`
