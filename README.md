# 博研助手 · Weibo Research Copilot

面向**社科类本科生与研究生**的微博舆论研究工具。

它不是商业舆情监测系统，而是**研究方法论驱动的数据采集与分析助手**：
每一个功能决策的首要判据是「是否服务于可复现的社科研究」，而不是「是否看起来智能」。

> 当前进度：**第 1 步（技术验证）已完成**。
> 详见 [`docs/DECISIONS/001-stage1.md`](docs/DECISIONS/001-stage1.md) 与 [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md)。

---

## 三条不可妥协的设计原则

1. **可追溯优先于自动化**
   任何派生结论都必须能回查到「模型版本 / 提示词版本 / 原始数据抽样」。
   工具不产出黑箱结论：清洗有报告、采集有日志、导出有校验和。

2. **可解释清洗优先于极限去噪**
   清洗的每一步对用户可见、可调、可关闭。
   社科研究里的「噪声」有时恰恰是研究对象（水军话术、情绪化表达），
   工具不替研究者做规范性判断。

3. **伦理合规内嵌而非事后补丁**
   匿名化与知情同意是链路的一部分：导出数据默认不含用户 ID / 昵称 / 主页 / 原始地区，
   交叉表中样本量 < 5 的单元格不予展示。

## 快速开始

### 方式一：图形界面（推荐）

```powershell
pip install -e .
```

然后**双击项目根目录的 `启动博研助手.vbs`** —— 不会弹出任何命令行窗口。

界面流程：扫码登录 → 填话题 → 点「检索帖子」→ 在列表里多选帖子 →
选清洗档位 → 勾选数据使用声明 → 点「一键完成：采集 → 清洗 → 分析 → 报告」。

> 一次点击会跑完全部步骤（含情感/立场分析与报告生成）。
> 只想先拿数据：在「4 · 分析与图表」里关掉「采集完成后自动分析」。
> 图表可选：在「4 · 分析与图表」里勾选要在报告里出现的图（14 种），
> 或命令行 `--charts sentiment_trend,stance_distribution`
> （完整清单：`python tools/run_analysis.py --list-charts`）。

> ⚠ **改动代码后必须关闭界面窗口重新启动。** Python 不会热更新已加载的模块，
> 界面开着旧代码却打出新行为，会让人误判成 bug（本项目已发生过一次）。
> 界面标题带版本号、日志每行带时间戳，就是为了一眼对出来。

### 方式二：命令行

```bash
# 环境自检（登录 / AI / 浏览器）
python -m wrc.cli doctor

# 扫码登录
python -m wrc.cli login

# 看看话题下有哪些帖子
python -m wrc.cli preview --tag 小米SU7

# 全流程：采集 → 清洗 → 导出
python -m wrc.cli run --tag 小米SU7 --select 1,2 --comments 50 --consent

# 启用 AI 辅助清洗（需先按 docs/MODEL-SETUP.md 下载模型）
python -m wrc.cli run --tag 小米SU7 --select 1 --tier heavy --ai --consent
```

**关于浏览器**：Playwright 内置 Chromium 的下载在国内经常卡住（本项目实测 79MB 后停滞）。
工具会自动回退到本机已安装的 Chrome / Edge，所以**通常不需要执行下载**。

**关于登录**：实测（未登录基线）微博检索接口直接返回 `ok=-100`，
说明「不登录也能公开检索」这条路走不通，**登录态是硬前提**。

**关于 AI**：完全可选。不装模型时轻度/中度档正常可用；想要重度档或 AI 判定，
按 [`docs/MODEL-SETUP.md`](docs/MODEL-SETUP.md) 下两个文件（共 23MB）放进 `models/` 即可，**不需要 torch**。

**本机已安装就绪**（`python -m wrc.cli ai` 可查）。阈值 0.62 是用真实数据标定的，
不是拍脑袋定的；换模型或换语料后请重新标定：

```bash
python tools/calibrate_ai.py     # 用真实数据标定阈值
python tools/ai_preview.py       # 预览 AI 会删掉你数据里的哪些评论（只读）
```

### 分析模块（P1 + 立场维度）

```bash
python tools/run_analysis.py --limit 200   # 情感 + 立场 + 聚类 + 时间演变 + 回复结构 + 图表 + 报告
python tools/run_analysis.py               # 不带 --limit = 全量分析（界面默认也是全量）
python tools/run_analysis.py --no-stance   # 跳过立场分析
python tools/run_report.py                 # 从数据库重建报告与图表（不重跑 LLM）
```

也可以在界面里操作：采集完成后点「开始分析并生成图表与报告」。
报告同时产出 Markdown 与 **Word（.docx，含嵌入图表）** 两份。

**情感与立场是两个独立维度**，报告分两节：

| 维度 | 类别 | 回答什么问题 |
| --- | --- | --- |
| 情感 | 正面 / 中性 / 负面 | 网友情绪有多负面 |
| 立场 | 支持 / 反对 / 中立 / **无关** | 网友对这项政策是支持还是反对 |

「无关」指评论没在谈这项政策（签到、闲聊、纯表情），**不计入支持率与反对率**。

### 本地情感模型（可选）

```bash
python tools/fetch_model.py            # 下载推荐模型（279MB，无需 torch）
python tools/fetch_model.py --check    # 检查现状
```

默认模型是 `twitter-xlm-roberta-base-sentiment`（1.98 亿条推文训练，八种语言含中文）。
选型不是按下载量排行榜定的，而是**用真实微博评论对比过**：
2024 年发布的 5 类多语言模型虽然更新、收藏更多，但在中文口语上判定混乱
（"打卡"判 Very Negative），已被否决。详见 `tools/fetch_model.py` 的说明。

### 采集失败与补救

```bash
python -m wrc.cli clean --list                 # 看每个会话采了多少条、清洗了没有
python -m wrc.cli clean --run <会话ID>         # 对已采到数据的会话补跑清洗与导出
```

采集中途有帖子接口返回「暂无数据」（帖子被删/评论不可见）时，
**不会再中断整轮**：该帖跳过、记进研究日志、其余照常采，运行状态标为 `partial`。
只有一篇都没采到时才算失败。

### 人工复核（抽查表）

```bash
python tools/make_review_sheet.py --run <会话ID>              # 分层抽 20 条，算准确率用
python tools/make_review_sheet.py --run <会话ID> --mode disagreement  # 专门找提示词的毛病
```

产出的 CSV 里排好了「评论原文 / LLM 判定 / 本地通道判定 / 两通道是否一致」，
只留三列给人工填。抽样种子固定，同一会话重复生成是同一批样本。

### 事件前后对比（event study）

```bash
python tools/run_report.py --run <会话ID> --event 2026-09-29:政策公布:7:7
python tools/run_analysis.py --event 2026-09-10:官媒定调:14:14
python tools/run_report.py --run <会话ID> --no-events   # 忽略已保存的事件
```

- **事件日期必须由研究者指定**：工具不会用"评论量最大的那天"顶替——那是数据特征，不是事件。
- 前段是 `[事件日−N, 事件日)`，后段是 `[事件日, 事件日+N]`（含事件当天）。
- 每侧少于 30 条只报数、不给结论；两比例 z 检验只在期望频数 ≥5 时给 p 值。
- 事件参数会写回该会话，之后重建报告不用再传。

### 研究日志与可复现性附录（P2）

```bash
python -m wrc.cli appendix              # 生成可复现性附录（Markdown + Word）
python -m wrc.cli appendix --all        # 所有会话各一份
python -m wrc.cli appendix --show-paths # 附录里附带本机路径（默认不写）
python -m wrc.cli reclean               # 清洗重放校验：逐条比对，只读不写
```

附录产出到 `data/exports/<会话ID>/appendix.md` 与 `appendix.docx`，内容包括：
运行环境、采集参数、清洗明细、各分析模块的实际参数、模型文件 SHA-256、
产出文件校验和、**逐环节的复现等级**（LLM 标注会明确写"不可复现"），
以及给第三方的复核步骤。

`reclean` 会用当前代码重跑一遍清洗并与库中记录逐条比对——「清洗可逐位复现」
这句话是可验证的，不是写在纸上。

### 时间演变 / 回复结构 / 跨话题对比（P3）

```bash
python tools/run_compare.py                # 跨话题对比（先判断能不能比，再出表）
python -m wrc.cli compare --runs A,B       # 指定会话对比
python -m wrc.cli compare --all            # 连 mock 会话一起看（会有强烈告警）
```

- **时间演变**：按时段聚合情感占比，小样本时段不给数字、不参与趋势判断。
  曲线描述的是**已采集样本的时间分布**，不是平台全量舆论的演化。
- **回复结构**：二级评论关系图与"单点引爆 / 多点分散"形态判断；
  未采集二级评论时会明说"没采到"而不是"没人回复"。
- **跨话题对比**：mock 与 live、参数不同的采集会被判为不可比并说明原因；
  占比不可比时直接不出图。

## 交付物自检

导出目录是拿去写论文的东西，缺文件、漏列、口径不一致都不会让程序报错，
只会在几天后提交时才发现。所以：

```bash
python tools/check_deliverables.py              # 最近一次采集
python tools/check_deliverables.py --run <id>   # 指定会话

```

它查四层：**完整性**（11 个必需文件且非空）、**隐私**（不得出现 user_id 等可识别字段）、
**结构**（报告章节、图是否存在）、**口径**（报告与附录的检索口径/时间窗逐字一致）。
`python tools/check.py` 已经把它接进一键自检。

## 采集算法（按微博平台特性设计）

> 样本量三个旋钮：**候选帖子数**（20–500，默认 100）、**每帖评论数**（10–2000，默认 100）、
> **请求上限**（20–3000，默认 400）。界面会实时算出"期望样本 vs 需要多少次请求"，
> 冲突时直接告诉你实际大约能采多少条——不会等到采完才发现样本被上限截断。

微博评论区有三种互不兼容的读法，选错一种，样本代表性和研究问题就对不上。
采集口径集中在 `wrc/weibo/window.py`，界面与命令行共用同一套判断。

**平台事实**（实测，改动需重测）：

| 通道 | 每页 | 排序参数 | 时间单调 | 能否"翻到起点就停" |
| --- | --- | --- | --- | --- |
| 移动端 `comments/hotflow` | 约 10 条 | ❌ 忽略 | ❌ 热门流 | ❌ 不能 |
| 网页端 `statuses/buildComments` | 约 20 条 | ✅ `flow=0/1` | ✅ 按时间时 | ✅ 能 |
| 二级评论 `hotFlowChild` | 约 10 条 | ❌ | — | 默认不采 |

**三个口径**：

- **时间窗**：填了窗口后，「每帖评论数」指**窗口内**要凑够多少条。
  不是"先取 50 条再筛窗口"——那样窗口越大可用样本越少，
  而你会以为自己采到了 50 条。
- **排序**：选「时间优先」时，移动端后端会忽略它。工具不会假装成功：
  `sort_applied=false` 写进日志与参数，方法卡片里明说"排序未生效"。
- **停止条件**：只有时间单调的流才能"越过窗口起点即停"并宣称窗口已覆盖；
  热门流只能翻到够数或触顶，此时报告 `窗口未完整覆盖`，并说明原因。

**逐帖目标数**：小帖子过度采集、大帖子严重不足都是抽样偏差，所以每帖可以单独设目标。
界面勾选帖子后（✅ 复选框）点「设置勾选帖子的目标数…」。

**会写进报告的话**（可直接抄进方法部分）：

```
窗口 2026-09-01 00:00 ～ 2026-09-30 23:59；窗口内 312 条；
窗口外跳过 88 条；实际覆盖 2026-09-02 09:14 ～ 2026-09-29 22:40；
窗口未完整覆盖（见停止原因：budget_near_limit）
```

命令行等价写法：

```bash
python -m wrc.cli run --tag 延迟退休 --select 1,3 \
  --since 2026-09-01 --until 2026-09-30 \
  --comment-sort time --comments 50
```

## 清洗档位

| 档位 | 做什么 | 需要 AI |
| --- | --- | --- |
| 不清洗 | 保留全部评论 | 否 |
| 轻度 | 去重 + 去除纯表情/纯链接/纯@ | 否 |
| 中度（推荐） | 轻度 + 广告关键词过滤（每条记录命中了哪条规则） | 否 |
| 重度 | 中度 + AI 识别营销话术与协同行为（附带相似度） | 是 |

三个开关按需使用，互不冲突：

- **严格去重**：勾选 = 完全相同的内容跨帖只留一条；**取消勾选 = 完全不去重**
  （研究水军模板时应取消）
- **二级评论**：默认关闭，勾选后同时采集楼中楼（请求量翻几倍）
- **疑似僵尸号过滤**：默认关闭。⚠ 只能拿到粉丝数，拿不到注册时间，
  按粉丝数删人可能误伤真实的低互动用户

## 数据与隐私

- `data/auth/storage_state.json` 等价于一份登录凭证，只保存在本地，不要提交到仓库。
- `data/keys/pseudo_salt.bin` 是伪匿名盐：**丢了不会报错，但同一用户的伪 ID 会变**；
  如果需要多次导出可关联，请备份它。
- 导出目录内的 `manifest.json` 记录了每个文件的 SHA-256，可直接写入论文附录。

## 许可与使用边界

本工具用于学术研究场景。使用者需自行确认：

- 所在机构的伦理审查（IRB）要求；
- 微博平台的服务条款与 robots 约定；
- 数据不得用于商业目的，不得尝试重新识别个体。

工具本身不做验证码绕过、不采集非公开内容、不规避付费限制。
